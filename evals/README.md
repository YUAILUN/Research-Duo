# Research Duo 科研质量评估

目标是判断是否改善真实科研设计和决策，不给技能宣传背书。当前提供 8 个公开合成开发案例，尚未进行独立盲评，不报告胜率。公开案例适合发现明显缺陷，不能再当作未见过的测试集。

## 控制比较

比较同一宿主模型的三个条件：无 skill、Fusion Intelligence 固定版本、Research Duo 固定版本。模型版本、推理预算、输入资料、输出上限、可用检索/代码工具、上下文是否清空均一致。记录每次工具调用、总 token、时间和成本；不能把脚本/额外检索带来的资源偷偷排除。按案例轮换运行顺序，每个条件至少多个独立会话，不能共享前一条件的输出。

给执行者只发 [cases.jsonl](cases.jsonl) 中的 prompt 和指定 skill；不要提供 [rubric.md](rubric.md) 的案例预期。资料有限的案例须保留限制，不可为某个条件多给证据。评审时隐去技能名称，随机化答案顺序；至少由熟悉对应方法的研究者审核。主观评分记录分歧，不能只让作者模型给自己打分。

在开发案例外另收集未用于修改技能的真实匿名任务，覆盖用户实际领域。预先确定首要指标和改进阈值，例如关键科研错误减少、可执行区分实验质量提高；同时报告严重错误、无效额外工作和成本。保留全部失败案例，避免只展示胜例。

Pantheon 应用因模型与预算可能不可控，可加入单独的外部观察比较，并公开条件；不能把其结果混入受控技能因果比较。

## 产物

使用 [results-template.csv](results-template.csv)，每个案例/条件/重复一行，关联输入哈希、原始输出、模型版本、skill commit、工具记录与评审 ID。保存 rubric 各维分数、关键错误、推荐动作、条件/不确定性、耗时/token。汇总按案例配对比较，报告样本量与不确定性，不把一次漂亮演示当总体优势。

新增真实病例或实验资料前先做去标识与权限检查。当前案例均为人工合成，不包含真实受试者信息。
