# 结果更新与局部经验蒸馏

## 记录不是自我强化

运行开始冻结一个简短记录：决策问题与版本、候选动作、证据快照、关键假设、各候选结果的预测、推荐及翻转条件。结果到来后先对照原预测，不先改写理论来解释成功。

更新时输出：`新增/失效证据 → 受影响主张/J# → 需重算的决策 → 旧建议/新建议/变化原因`。可用 `audit` 的 `changed_ids` 找受影响的依赖。关联材料共享同源簇时检查整簇；脚本不会自动判断哪篇文章同源。撤回证据触发重审，不等于将其支持的主张自动判为假。

## 错误定位

- 框架错：优化了错误终点、错误人群或不可识别问题 → 重定目标与设计。
- 证据错：误读、同源重复、选择性遗漏 → 修正账本和下游。
- 判断错：判据模糊、选项覆盖不足、未知被迫分类 → 修订原子契约。
- 效用错：成本、损失或偏好被错设 → 重新征询/做情景，不改写事实。
- 组合错：必要条件被高分抵消、单位混用 → 修正规则与回归例。
- 迁移错：在不同机制、人群或时间沿用旧规则 → 缩小适用边界。

## 经验卡（decision capsule）

只为反复出现且确有验证记录的局部判断创建，用户请求/授权保存时写入指定目录；默认在当前研究产物中保留，不自动修改全局技能。

```text
ID / 版本 / 日期：
适用问题、系统、人群与时间范围：
必要输入与排除条件：
规则（if 条件 → 建议动作，否则 → 明确退回路径）：
支持证据及独立性局限：
已验证案例与尚未验证边界：
反例 / 已知失败：
重新验证触发器（新证据、环境或指标变化、到期条件）：
维护者 / 更新记录：
```

没有历史检验的卡标为“候选规则”，只可提示探索，不能走快速推荐通道。成功案例和失败案例都保留；不能只用同一模型对自己输出的赞同作为验证。任何压缩都保留反例与边界。

## 校准与持续评估

只有事前记录的概率预测和可核实的实际结局，才能计算 `calibrate` 的 Brier、ECE 与选择性错误率。模型自评、角色投票比例、效用分数、ordinal 分值都不是这种概率。保持训练/选择与检验分离，报告样本量、时间、人群和分布变化。

脚本给描述统计，不估置信区间，不确定生产阈值，不训练校准器；小样本 ECE 不能证明可靠。概率缺失时直接检查预测是否可证伪、关键错误和决策遗憾，无需硬造数字。
