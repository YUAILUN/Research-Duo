# Jev 设计思路的蒸馏：可迁移的接口与不可声称的能力

Jev 的公开设计把状态与原子问题分离，以类型约束输出，再由显式逻辑组合判断。本项目借鉴这一接口思想，在宿主模型上实现科研工作协议与本地计算；没有 Jev 调用、模型权重或 RLCD 训练。官方材料见 [TypeSafe 介绍](https://docs.typesafe.ai/introduction)及 [发布文章](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。

| 设计启发 | Research Duo 的原创转化 | 边界 |
| --- | --- | --- |
| 有边界的原子判断 | 一个判断只回答一个可判定问题，先写判据再填值 | 原子化不能补足缺失证据 |
| 类型化接口 | choice / ordinal / predicate + 显式 null | 宿主仍生成文本，必须解析校验；并非原生类型模型 |
| 状态与问题分离 | 固定证据快照、版本与证据 ID；把价值权重放在决策层 | 同模型/同资料的多个判断仍相关 |
| 判断与组合分离 | 必要条件门控、显式效用、EVSI、遗憾计算 | 决策规则和效用仍需研究者审查 |
| 不确定性参与路由 | 未知→补证，冲突→审议，问题错误→重构，脆弱→情景比较 | 路由只检查输入声明，不验证科学事实 |
| 高频局部决策复用 | 有适用范围、反例、验证记录和失效触发器的经验卡 | 提示压缩不是训练，也不产生新参数或校准 |

## 防止把“系统一”误读为直觉优先

快速通道只用于已有证据、适用范围清楚且经压力测试的可逆局部判断。新机制、分布改变、相互矛盾证据、不可识别的因果问题应交给探索与重构。先投入推理把问题拆对，才能把重复判断缩短。

不要把“最优研究方向是什么”伪装成单个选择题。拆成可识别性、关键机制证据、测量有效性、资源匹配、信息价值等判断；先决定哪些是必要条件，再由显式规则组合。彼此依赖的判断要分阶段，后一阶段引用已冻结的前序结果。

## 三个不可移植的承诺

1. Jev 的训练算法、原生输出保证和速度基准不属于这个技能。
2. 官方 confidence 的某些定义是输出分布的集中度，不能直接当成任务正确率。宿主自报 95% 同样不等于校准概率。参见 [Confidence](https://docs.typesafe.ai/confidence)。
3. 类型合法不代表事实零幻觉。官方也披露数值推理、上下文和输入扰动等弱点；本技能不沿用“零幻觉”的科学准确性承诺。参见 [已知能力边界](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 何时真的能变好

预期改进来自把错误定位在可检查的位置：问题框架、证据、判断、效用或组合规则。衡量它是否让研究问题更可识别、实验更能区分假设、决定更可复现，而不是统计发言人数或答案长度。优于 Pantheon / Fusion Intelligence 是待实验检验的目标，不是当前已证事实。
